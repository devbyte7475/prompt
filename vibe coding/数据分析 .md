#### **📌 分析步骤要求（动态适应数据特征）**

1. **数据概览与质量检查**  
   - 说明数据行数、列数、类型分布。  
   - **动态检查关键点**（AI需根据实际列名自动判断）：  
     - 若存在**日期列**（如`date`/`order_date`）：检查是否按`YYYY-MM-DD`格式。  
     - 若存在**分类列**（如`status`/`type`）：检查值是否标准化（避免大小写/空格差异）。  
     - **缺失值处理**：基于列业务意义提建议（例：若`price`缺失，建议用中位数填充；若`promo_type`缺失，建议按历史分布填充）。  

2. **探索性数据分析（EDA）**  
   - **动态生成可视化建议**（AI根据列特征自动选择）：  
     - 若含**数值列**：推荐3个核心图表（如：箱线图看异常值、散点图看相关性、直方图看分布）。  
     - 若含**时间序列**：必须推荐**时序图**（如销售额随时间变化趋势）。  
     - 若含**分类列**：推荐**条形图**（如各类型占比）或**热力图**（如类型与数值列关联）。  
   - **关键要求**：每个图表需说明**如何解决业务痛点**（例：*“销量与促销类型热力图 → 定位高转化促销类型”*）。

3. **特征工程建议**  
   - **动态创建新特征**（基于业务逻辑和数据特征）：  
     - 例：若存在`date`列 → 建议`month`/`day_of_week`特征。  
     - 例：若存在`user_id`和`transaction_date` → 建议`days_since_last_transaction`。  
   - **编码建议**：  
     - 若分类列**值数量少**（10）→ 目标编码（保留业务语义）。  

4. **建模建议**  
   - **动态选择模型**（AI根据数据特征判断）：  
     | 数据特征                | 推荐模型                | 原因                     |
     |------------------------|------------------------|--------------------------|
     | 含**时间序列**（如`date`） | Prophet/XGBoost+时序特征 | 自动处理时间依赖性         |
     | **无时间序列**          | XGBoost/随机森林        | 通用性强，解释性好         |
     | **数据量极小**（<1000行）| 线性回归/决策树         | 避免过拟合               |
   - **数据划分**：  
     - **若含时间列** → 按时间顺序划分（训练集：早于测试期）。  
     - **若无时间列** → 随机划分（但需说明比例，如`70%训练, 30%测试`）。  
   - **评估指标**：  
     - **预测类** → 用`RMSE`/`MAPE`（避免`accuracy`）。  
     - **分类类** → 用`F1-score`（避免`accuracy`）。  

5. **潜在挑战与注意事项**  
   - **动态排查风险**（AI需根据数据特征自动生成）：  
     | 风险类型          | 检查点（AI自动判断）                  | 应对方案                  |
     |-------------------|-------------------------------------|-------------------------|
     | **数据偏差**      | 检查关键列分布是否均衡（如`promo_type`占比） | 分层抽样/加权处理         |
     | **时间序列泄露**  | 检查是否按时间划分数据               | 重划数据集（时间顺序）     |
     | **特征冗余**      | 检查相关性矩阵（>0.8的变量对）        | 删除高相关变量或合并特征   |

#### **📌 输出格式要求（通用标准）**
- **所有结论用业务语言**（例：*“促销活动使销售额平均提升15%”*，非*“促销类型系数=1.5”*）。  
- 使用Markdown组织，每个步骤用**二级标题**（如`## 1. 数据概览与质量检查`）。  
- **避免行业术语**（如不写“RFM分群”“购物车放弃率”），用**通用描述**（如“用户行为链路分析”）。  
- **关键洞察与业务痛点强关联**（例：业务痛点“波动率上升”→分析指出“促销类型A在波动期效果最佳”）。
