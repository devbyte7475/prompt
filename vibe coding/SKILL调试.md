# SKILL 技能包调试通用 SOP

本文档定义了调试 Trae IDE 中 SKILL 技能包的标准操作流程，适用于任何类型的技能包调试。

---

## 一、需求分析阶段

| 步骤 | 操作 | 方法 |
|------|------|------|
| 1.1 | 理解技能包功能 | 阅读 SKILL.md 的 `name` 和 `description` |
| 1.2 | 识别用户痛点 | 分析用户反馈和问题 |
| 1.3 | 确定优化目标 | 功能增强/性能优化/体验改善/错误修复 |
| 1.4 | 评估影响范围 | 确定需要修改的文件和模块 |

**输出物**：优化目标清单

---

## 二、结构审查阶段

| 步骤 | 操作 | 工具/方法 |
|------|------|----------|
| 2.1 | 查看目录结构 | `LS` 工具，了解文件组织 |
| 2.2 | 阅读核心文件 | `Read` 工具，阅读 SKILL.md |
| 2.3 | 检查文件关联 | `Grep` 搜索跨文件引用 |
| 2.4 | 识别内容重复 | 对比各文件内容 |

**检查清单**：

```
□ SKILL.md 是否存在且格式正确
□ 必要的子目录是否存在
□ 文件命名是否规范
□ 引用路径是否有效
```

---

## 三、内容优化阶段

| 步骤 | 操作 | 原则 |
|------|------|------|
| 3.1 | 移除重复内容 | 同一信息只保留一处 |
| 3.2 | 精简冗余说明 | 保留核心，删除冗余 |
| 3.3 | 优化文档结构 | 使用表格、列表、分级标题 |
| 3.4 | 统一格式风格 | 保持一致的 Markdown 格式 |

**优化原则**：

- **DRY 原则**：不重复（Don't Repeat Yourself）
- **单一职责**：每个文件专注一个主题
- **引用优于复制**：用链接指向详细文档

---

## 四、功能完善阶段

| 步骤 | 操作 | 说明 |
|------|------|------|
| 4.1 | 梳理操作流程 | 将功能分解为清晰的步骤 |
| 4.2 | 补充缺失步骤 | 确保流程完整（初始化→执行→清理） |
| 4.3 | 添加容错机制 | 异常处理、备选方案 |
| 4.4 | 完善配置存储 | 用户配置的持久化方案 |

**流程规范模板**：

```markdown
### 操作流程

1. **初始化** - 准备工作（检查环境、获取配置）
2. **执行** - 核心操作（具体步骤）
3. **验证** - 确认结果（检查输出）
4. **清理** - 释放资源（删除临时文件）
```

## 五、移植性优化阶段

| 步骤 | 操作 | 方法 |
|------|------|------|
| 5.1 | 识别硬编码 | 搜索绝对路径、特定用户名、特定 IP 等 |
| 5.2 | 定义变量 | 创建路径变量、配置变量 |
| 5.3 | 替换硬编码 | 全局替换为变量引用 |
| 5.4 | 添加变量说明 | 在文件开头定义变量含义 |

**常见硬编码类型**：

| 类型 | 示例 | 解决方案 |
|------|------|---------|
| 绝对路径 | `/Users/tank/...` | 使用 `{SKILL_ROOT}` 等变量 |
| 用户名 | `devbyte7475` | 配置化，存储到 `user_config.yaml` |
| API Key | `sk-xxx` | 配置化，运行时提供 |
| IP/端口 | `localhost:8080` | 配置化或动态获取 |

**变量定义模板**：

```markdown
## 📁 路径变量

| 变量名 | 说明 | 获取方式 |
|--------|------|---------|
| `{SKILL_ROOT}` | 技能包根目录 | 当前 SKILL.md 所在目录 |
| `{PROJECT_ROOT}` | 项目根目录 | 技能包的上级目录 |
| `{CONFIG_FILE}` | 配置文件 | `{SKILL_ROOT}/assets/user_config.yaml` |
```

## 附录：常见问题与解决方案

### 问题 1：路径硬编码

**现象**：技能包在不同环境无法运行

**解决方案**：
1. 定义路径变量
2. 使用相对路径
3. 配置化用户特定信息

### 问题 2：内容重复

**现象**：多个文件包含相同内容

**解决方案**：
1. 识别重复内容
2. 保留一份权威版本
3. 其他位置使用链接引用

### 问题 3：流程不完整

**现象**：执行后残留临时文件或状态

**解决方案**：
1. 添加清理步骤
2. 使用 try-finally 模式
3. 记录操作日志便于回滚

### 问题 4：配置丢失

**现象**：用户配置无法持久化

**解决方案**：
1. 创建 `assets/user_config.yaml`
2. 定义配置结构
3. AI 自动读写配置
